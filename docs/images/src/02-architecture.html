How the whole thing stays running

Five independent mechanisms. None depends on another being healthy — a single supervisor is a single point of failure.

The proxy

  • Redacts literals + 27 patterns
  • Aliases identity, restores it inbound
  • Normalises timezone, locale, headers
  • Serves the dashboard on the same port

Staying alive

  • SessionStart hook — starts it, waits for health
  • Startup folder — up before your first session
  • Scheduled task — crash repaired ≤ 5 min
All three run the same idempotent check. None needs admin.

Egress · fail closed

VPN masking? → tunnel idle
VPN drops? → tunnel engages
no tunnel? → REFUSED
An outage, never a silent exposure.

On-disk residue

  • Transcripts are written before anything is sent
  • Scrubbed hourly with the same pipeline + key
  • Per-run log and per-file manifest

Audit

  • Every scrub pass, durably recorded
  • Every retention sweep — including ones that removed nothing
  • Signals: staleness, failures, spikes
"Nothing to do" and "silently stopped" must not look alike.

Retention

  • Every log has a configurable TTL
  • The retention log governs itself
  • Raw change logs: 7 days, owner-only
Old records are a disk problem and a data-exposure problem.

Every other tool reports on one component. The two worst failures this project had lived in the gaps between components — and both showed green everywhere anyone thought to look.
